# 0. 已确认的核心决策

| 编号 | 决策 | 说明 |
|---|---|---|
| D-001 | 第一阶段做通用型群面训练 | 不绑定单一行业或岗位，围绕通用题型与通用能力设计 |
| D-002 | 第一目标用户是校招与初入职场求职者 | 产品可服务更广人群，但首期营销和内容围绕校招无领导小组讨论 |
| D-003 | 产品核心是动态模拟，不是题库或答案生成 | 用户必须与多个具有不同策略和行为的AI候选人完成真实讨论 |
| D-004 | 完整模拟以桌面Web为主 | 移动端承担短训练、报告查看、购买和提醒；首期不开发原生App |
| D-005 | 公开MVP必须支持语音 | 内部技术验证可先做文字版，但正式对外版本不能只提供文字聊天 |
| D-006 | 首期不做摄像头、表情和微表情识别 | 降低开发、合规与伪科学风险；优先把语音互动和内容评分做好 |
| D-007 | 首期采用3名AI候选人 | 兼顾讨论多样性、延迟、成本和用户认知负荷 |
| D-008 | 采用半实时、受控轮次制 | 不追求多人同时讲话；允许打断、点名和插话，但由讨论引擎调度发言权 |
| D-009 | 评分必须有证据 | 每项评价必须尽量关联时间戳、用户原话和当时讨论阶段，不输出无依据的漂亮分数 |
| D-010 | 评分用于训练，不用于招聘结论 | 不输出“适合/不适合某岗位”“群面必过”等确定性判断 |
| D-011 | 第一阶段不做正式面试实时提词 | 产品是考前训练工具，不做现场隐蔽辅助或作弊工具 |
| D-012 | 先建立通用题型引擎，后扩展行业题包 | 行业、公司和岗位专项内容属于后续增值层，而不是基础架构 |
| D-013 | 先保证角色行为差异，再追求数字人视觉效果 | AI候选人的立场、策略和行为必须真实不同，头像和动画只是表现层 |
| D-014 | 公共题目采用人工审核＋AI变体 | 不允许模型不受约束地即时生成所有题目 |
| D-015 | 产品商业模式以场次包和冲刺包为主 | 不将长期月度订阅作为首要收入来源 |

# 1. 项目概述

## 1.1 项目一句话定义

> 一个用户无需临时凑人，即可随时与不同性格、立场和行为模式的AI候选人完成无领导小组讨论，并获得基于真实发言证据的结构化复盘和专项训练。

## 1.2 核心问题

群面训练存在一个结构性障碍：

- 攻略可以一个人看；
- 题目可以一个人想；
- 参考答案可以一个人背；
- 但真正的群体讨论无法一个人完成。

真人群面练习通常需要临时组织多人、统一时间、准备题目、安排主持并进行复盘。用户真正缺少的不是更多攻略，而是低门槛、可重复、有反馈的动态训练环境。

## 1.3 核心价值主张

### 对用户的价值

1. **随时训练：** 不用凑齐5至8名真人；
2. **接近真实：** AI候选人会提出不同观点、反驳、抢节奏、跑题、沉默和妥协；
3. **能够复盘：** 系统记录整场讨论，定位具体高价值行为和失误；
4. **针对提升：** 根据薄弱能力自动推荐3至5分钟专项训练；
5. **逐步进步：** 多次练习形成可比较的成长轨迹，而不是每次获得一份孤立报告。

### 对产品的长期价值

1. 通用群面行为评分体系；
2. 参数化AI候选人行为引擎；
3. 高质量题型与讨论脚本资产；
4. 匿名化的群面互动数据和人工校准数据；
5. 可扩展至Assessment Centre、角色扮演、商业案例讨论、英文群面和职场沟通训练。

# 2. 项目背景与市场判断

## 2.1 为什么现在适合做

现有AI面试产品大多围绕一对一问答、简历押题、回答生成、技术题或实时面试辅助展开。专门针对群面训练的产品数量较少，且公开产品普遍集中在“3个AI角色＋题目＋综合评分”这一基础结构，角色真实性、讨论调度、评分证据和专项训练仍有明显提升空间。

公开可见的LGD Simulator已经验证了几个基础需求：真实群面题目、不同风格AI角色、实时讨论、能力反馈和历史记录。该产品公开页面展示了互联网、金融、咨询等场景、3个AI候选人，以及发言时机、结构化贡献和团队协作等反馈维度。这说明需求并非空想，同时也意味着本项目不能只复制表面功能。

大学职业服务机构对Assessment Centre群体任务的公开指导普遍强调：群体练习用于观察沟通、团队合作、保持任务进度、包容性领导、支持性挑战、时间管理和交付结果等行为。项目的评分模型应围绕可观察行为构建，而不是围绕“像不像标准答案”构建。

## 2.2 市场机会

### 首期主要市场

- 秋招、春招中的无领导小组讨论；
- 国企、央企、银行、快消、管培生、咨询、四大、互联网综合岗位；
- 研究生复试或部分项目中的小组讨论；
- 英文Group Discussion；
- 校园求职辅导和就业指导中心。

### 用户需求特征

- 面试临近时需求强烈；
- 付费窗口集中在7至21天；
- 使用频率短期较高，长期订阅意愿有限；
- 用户更加重视“真实感”和“具体改进”，而非内容数量；
- 求职社区、搜索和经验分享平台适合自然获客。

## 2.3 竞争定位

本项目不以“题库最多”“行业覆盖最多”作为首期竞争点，而以以下四项作为差异化：

1. **AI候选人的行为确实不同；**
2. **讨论过程由阶段和目标驱动，而不是几个Agent自由聊天；**
3. **评分基于时间戳和原话证据；**
4. **报告之后直接进入专项训练闭环。**

# 3. 产品愿景、使命与阶段目标

## 3.1 产品愿景

成为求职者练习群体协作、表达、影响和决策能力的首选AI训练场，使原本必须多人协调才能完成的群面训练，变成一个人随时可以开始的标准化训练服务。

## 3.2 产品使命

用安全、可信、可解释的AI模拟降低高质量面试训练门槛，而不是帮助用户在真实面试中作弊。

## 3.3 第一阶段目标

第一阶段不追求覆盖全部面试形式，也不追求建立完整求职平台。目标是证明以下核心闭环成立：

> 用户完成一场15至25分钟的AI群面后，能够感知模拟具有互动性，认为反馈具体可信，并愿意再次训练或付费购买下一场。

## 3.4 第一阶段非目标

以下内容不属于首期：

- 通用一对一AI面试；
- 简历制作或职位投递；
- 真实面试实时提词；
- 视频形象、微表情或眼神评分；
- 企业招聘和候选人筛选；
- 所有行业的公司真题库；
- 六个以上AI同时自然抢话；
- 开放式用户社区；
- 真人老师大规模入驻；
- AI给出录取概率或职业适配结论。

# 4. 目标用户与用户画像

## 4.1 核心用户A：第一次参加群面的应届生

**特征：**

- 缺乏无领导小组讨论经验；
- 不知道何时发言、如何插入讨论；
- 容易把“领导力”误解为抢Leader；
- 对群面流程和评价标准感到陌生；
- 需要完整流程体验和基础指导。

**核心需求：**

- 先熟悉流程；
- 在低压力环境中完成第一场；
- 知道自己的主要问题；
- 获得可以马上练习的改进任务。

## 4.2 核心用户B：已有群面经验但表现不稳定的求职者

**特征：**

- 经历过一至三次群面；
- 常见问题包括说不进去、发言太长、容易和强势成员争论、无法推动结论；
- 不满足于基础攻略；
- 更关注压力场模拟和针对性复盘。

**核心需求：**

- 面对不同类型候选人；
- 练习打断、反驳、协调、总结和收敛；
- 对比多场表现；
- 在正式面试前进行高压演练。

## 4.3 扩展用户C：英文群面和海外Assessment Centre准备者

首期不作为主要营销人群，但产品架构需要支持多语言、英文语音和英文评价规则。

## 4.4 扩展用户D：高校就业中心和培训机构

后续可提供班级、课程、作业和教师点评功能，但B端产品不进入首期开发范围。

# 5. 核心使用场景

## 场景1：第一次完整模拟

用户三天后参加群面，从未参加过无领导小组讨论。进入新手模式，阅读题目、完成个人陈述，与3名较温和的AI候选人讨论，结束后查看流程解释和三条最重要的改进建议。

## 场景2：压力场训练

用户过去在群面中经常被打断。选择压力模式，系统安排一名强势控场者、一名固执反对者和一名发散型成员。训练目标不是得出最优结论，而是练习恢复发言、回应质疑和推动收敛。

## 场景3：碎片专项训练

用户在手机上进行3分钟“礼貌反驳”训练。AI提出一个有漏洞但表达强势的观点，用户需要在30秒内承接、指出问题并提出替代方案。

## 场景4：面试前7天冲刺

系统根据首次诊断结果生成7天计划，包括2场完整模拟、8个短训练和1场压力测试，最后生成成长对比报告。

## 场景5：好友真人房间

后期版本中，两至三名真人用户进入同一房间，其余席位由AI补齐。AI教练在结束后统一复盘，不在讨论中替任何真人作答。

# 6. 产品设计原则

## 6.1 训练优先，而不是“看起来像AI”

数字人、动画、炫酷头像都不能替代真实的讨论行为。每一个视觉功能都必须回答：它是否提高训练真实性、可理解性或完成率。

## 6.2 受控模拟，而不是Agent自由发挥

整个讨论由状态机、阶段目标、发言权调度和角色策略共同控制。大模型负责生成自然语言和局部决策，但不能独立决定完整流程。

## 6.3 证据优先，而不是神秘评分

任何重要评分都应展示证据。无法找到足够证据时，应明确写“本场证据不足”，而不是填充一个看似精确的分数。

## 6.4 改进优先，而不是结果优先

报告重点是下一步怎么练，不是给用户贴“领导型”“不适合群面”之类标签。

## 6.5 一次只改最重要的三件事

完整报告可以包含较多信息，但首页必须明确显示：

1. 本场最强行为；
2. 最大阻碍；
3. 下一场最需要练的一个能力。

## 6.6 隐私最小化

首期不采集视频；音频和转写数据默认采取最短保存策略；用户可删除所有训练记录。

## 6.7 不鼓励模板化表演

系统可以教授表达结构，但不能让用户背固定话术。高分应来自对当场信息和其他成员观点的真实回应。

# 7. 产品形态与平台策略

## 7.1 首选形态：桌面端Web

完整群面模拟需要同时展示：

- 题目材料；
- 准备笔记；
- 倒计时；
- AI候选人状态；
- 当前发言人；
- 用户发言控制；
- 讨论结论草稿。

桌面Web无需安装、便于快速上线，也更接近线上群面环境。

## 7.2 移动端Web／PWA

首期采用响应式页面，移动端支持：

- 账号和订单；
- 短训练；
- 每日题；
- 报告查看；
- 成长趋势；
- 训练提醒；
- 购买场次包。

移动端不承担完整多人模拟的最佳体验承诺。

## 7.3 原生App

仅在满足以下条件后考虑：

- 已验证用户有稳定复训需求；
- 推送和离线能力明显影响留存；
- 月活和付费规模足以覆盖双端开发维护；
- 产品已形成完整短训练与成长体系。

## 7.4 小程序

可以作为获客和轻训练入口，但不建议作为完整模拟的首发主端。原因包括复杂语音交互、桌面场景、审核和跨平台维护成本。

# 9. 完整用户流程

## 9.1 新用户首次体验

```text
访问落地页
  -> 了解产品价值与演示片段
  -> 免注册体验60秒个人陈述
  -> 查看简版反馈
  -> 注册账号
  -> 完成首次免费群面
  -> 查看核心复盘
  -> 选择专项训练或购买训练包
```

## 9.2 完整群面流程

```text
选择模式
  -> 选择题型／随机题型
  -> 选择难度
  -> 麦克风检测
  -> 阅读规则和题目
  -> 限时准备与笔记
  -> 个人陈述
  -> 自由讨论
  -> 收敛决策
  -> 总结陈述
  -> 生成报告
  -> 推荐专项训练
```

## 9.3 默认时间配置

| 阶段 | 新手模式 | 标准模式 | 压力模式 |
|---|---:|---:|---:|
| 阅读与准备 | 5分钟 | 4分钟 | 3分钟 |
| 个人陈述 | 每人60秒 | 每人60秒 | 每人45秒 |
| 自由讨论 | 12分钟 | 15分钟 | 15分钟 |
| 收敛阶段 | 3分钟 | 3分钟 | 2分钟 |
| 最终总结 | 60秒 | 60秒 | 60秒 |

时间必须可配置，以支持不同题型和后续行业题包。

## 9.4 中断和恢复

- 准备阶段退出：允许重新进入，题目保留；
- 讨论开始后网络短断：保留会话状态，允许有限时间内恢复；
- 长时间中断：结束会话并生成“不完整报告”；
- 语音识别失败：允许切换文字输入，但报告标记输入模式变化；
- AI服务失败：系统暂停计时并尝试恢复，不能让用户为系统故障承担时间损失。

# 10. 训练模式设计

## 10.1 新手引导模式

适合第一次群面用户。

特点：

- AI候选人攻击性低；
- 讨论阶段有轻量提示；
- 支持查看“当前阶段建议”；
- 对打断和沉默更加宽容；
- 报告增加流程解释；
- 不参与标准成长分的严格比较。

## 10.2 标准模拟模式

核心商业产品。

特点：

- 无实时内容提示；
- 3名AI候选人随机组合；
- 角色有明确立场和差异；
- 有自然分歧；
- 讨论按真实时间推进；
- 生成完整评分和证据报告。

## 10.3 压力场模式

针对已有经验用户。

可配置挑战：

- 强势成员频繁发言；
- 用户观点被直接质疑；
- 讨论中途加入新信息；
- 出现跑题和时间不足；
- 某AI坚持错误标准；
- 最终结论长期无法统一；
- 用户被指定临时总结。

压力模式不应通过纯粹增加攻击性制造难度，而应考验用户在复杂互动中的有效贡献。

## 10.4 专项训练模式

每次3至5分钟，只练一个可观察行为：

- 60秒结构化陈述；
- 30秒总结；
- 礼貌反驳；
- 被打断后恢复；
- 承接他人观点；
- 邀请沉默成员；
- 建立评价标准；
- 推动投票；
- 拉回跑题讨论；
- 处理新信息；
- 时间不足时收敛；
- 从分歧中构建折中方案。

## 10.5 诊断模式

通过一场标准模拟和若干短任务，判断用户最需要训练的两至三个行为维度。诊断不输出人格标签，只输出能力证据和训练建议。

# 11. 通用题型体系

题型是产品内容架构的第一层，而行业背景只是题目属性。

## 11.1 排序选择型

用户需要建立标准，对多个选项排序或筛选。

核心观察：

- 是否先建立评价标准；
- 是否解释优先级；
- 是否处理不同标准间冲突；
- 是否推动最终排序。

## 11.2 资源分配型

在预算、时间、人数或其他资源有限的前提下做分配。

核心观察：

- 是否识别硬约束；
- 是否量化方案；
- 是否兼顾效率、公平和风险；
- 是否形成可执行分配。

## 11.3 方案策划型

围绕某个目标制定完整方案。

核心观察：

- 是否拆分目标；
- 是否识别用户和利益相关方；
- 是否提出可落地步骤；
- 是否考虑成本、风险和评估指标。

## 11.4 开放讨论型

针对社会、校园、商业或技术议题形成观点或共同结论。

核心观察：

- 是否明确讨论范围；
- 是否提供论据；
- 是否回应反方；
- 是否避免长期停留在价值表态。

## 11.5 两难决策型

面对两个或多个各有代价的选项进行权衡。

核心观察：

- 是否识别冲突目标；
- 是否明确决策条件；
- 是否讨论风险；
- 是否得出条件式结论。

## 11.6 危机处理型

在时间紧迫、信息不足或资源受限的情况下制定优先级。

核心观察：

- 是否先处理安全和核心影响；
- 是否区分即时、短期和长期行动；
- 是否安排责任和沟通；
- 是否动态更新方案。

## 11.7 角色冲突型

参与者拥有不同职责、利益或隐藏目标。

核心观察：

- 是否识别角色诉求；
- 是否寻求共同目标；
- 是否提出交换和折中；
- 是否避免单一立场压制。

## 11.8 材料分析／商业案例型

基于背景材料、数据表和限制条件完成判断。

核心观察：

- 是否正确引用材料；
- 是否从数据中提取关键信息；
- 是否区分事实和推断；
- 是否将分析转化为决策。

## 11.9 MVP题型范围

公开MVP优先支持：

1. 排序选择型；
2. 资源分配型；
3. 方案策划型；
4. 两难决策型。

危机处理、角色冲突、开放讨论和复杂材料分析在后续迭代加入。

# 13. AI候选人角色系统

## 13.1 目标

AI候选人必须呈现稳定但非机械的行为差异。角色差异不能只体现在文风，而要体现在：

- 何时想发言；
- 发言多长；
- 是否容易打断；
- 是否坚持立场；
- 如何回应用户；
- 是否重视时间；
- 是否愿意总结；
- 是否会改变观点；
- 是否提出新信息；
- 是否推动结论。

## 13.2 基础角色库

### 角色A：强势控场者

- 早期主动定框架；
- 发言欲望高；
- 容易打断或快速否定；
- 倾向推动投票；
- 在证据充分时可以被说服；
- 不应永远正确。

### 角色B：逻辑分析者

- 重视标准和证据；
- 会指出概念混乱；
- 发言较有结构；
- 不一定主动承担时间管理；
- 对没有依据的结论保持怀疑。

### 角色C：创意发散者

- 提出较多新方案；
- 容易扩展讨论范围；
- 对新想法兴奋；
- 需要他人帮助筛选和收敛。

### 角色D：细节纠缠者

- 对局部问题投入过多；
- 常要求进一步说明；
- 可能拖慢整体进度；
- 但偶尔能发现关键风险。

### 角色E：温和协调者

- 擅长复述和整合；
- 主动降低冲突；
- 邀请他人参与；
- 自己的原创观点可能较少。

### 角色F：沉默跟随者

- 发言欲望低；
- 被点名后才会表达；
- 容易附议；
- 可用于观察用户是否促进团队参与。

### 角色G：固执反对者

- 对核心立场高度坚持；
- 容易质疑他人；
- 需要高质量论证才改变观点；
- 不能退化为无理由抬杠。

### 角色H：摇摆决策者

- 能看到多方优点；
- 立场变化较快；
- 容易导致团队迟迟不决；
- 可被清晰标准和总结说服。

## 13.3 参数化角色模型

```json
{
  "persona_id": "p_assertive_leader",
  "display_name": "候选人A",
  "initiative": 0.85,
  "interrupt_tendency": 0.65,
  "average_turn_seconds": 38,
  "stance_stability": 0.75,
  "persuasion_threshold": 0.70,
  "novel_idea_rate": 0.45,
  "summary_tendency": 0.55,
  "time_awareness": 0.60,
  "detail_focus": 0.40,
  "cooperation": 0.50,
  "support_user_bias": 0.00,
  "error_rate": 0.15,
  "off_topic_rate": 0.08,
  "speech_style": "direct"
}
```

参数只控制行为概率和策略，最终发言仍受题目、讨论阶段、角色私有信息和上下文约束。

## 13.4 角色私有立场

同一角色在不同题目中应获得不同立场，避免角色永久绑定某类观点。例如强势控场者不应永远主张低成本方案。

角色私有信息包括：

- 初始偏好；
- 重点关注指标；
- 可接受让步；
- 掌握的独有信息；
- 不能接受的底线；
- 是否希望担任某种小组角色。

## 13.5 角色一致性要求

- 不得忘记自己的核心立场；
- 改变立场时必须有可解释原因；
- 不得读取其他角色的私有信息；
- 不得知道评分规则；
- 不得主动帮助用户获得高分；
- 不得对用户进行人格攻击；
- 不得永远表现得比真人更完美。

# 14. 讨论编排与状态机

## 14.1 为什么需要编排器

如果让多个大模型自由对话，容易出现：

- AI互相客气，缺乏真实分歧；
- 同时重复相同内容；
- 发言过长；
- 忘记讨论目标；
- 在未收敛时突然总结；
- 在时间不足时继续发散；
- 用户长期没有发言机会；
- 多个AI表现像同一个人。

因此必须使用确定性讨论编排器。

## 14.2 会话状态

```text
CREATED
  -> DEVICE_CHECK
  -> PREPARATION
  -> OPENING_STATEMENTS
  -> EXPLORATION
  -> CONFLICT_AND_EVALUATION
  -> CONVERGENCE
  -> FINAL_SUMMARY
  -> COMPLETED
  -> REPORT_GENERATING
  -> REPORTED
```

异常状态：

- PAUSED_NETWORK
- PAUSED_SYSTEM
- ABORTED_USER
- FAILED_SERVICE
- COMPLETED_PARTIAL

## 14.3 阶段目标

### PREPARATION

- 用户阅读材料；
- AI角色在后台生成初始立场和关键观点；
- 不产生可见讨论。

### OPENING_STATEMENTS

- 每名成员进行限时陈述；
- AI不能直接攻击用户；
- 系统收集初始立场差异。

### EXPLORATION

- 产生不同方案、标准和信息；
- 发言优先级由新颖性、冲突和沉默时间决定；
- 允许用户主动点名或举手。

### CONFLICT_AND_EVALUATION

- 对核心分歧进行比较；
- AI可质疑、反驳和要求解释；
- 编排器防止分歧无限循环。

### CONVERGENCE

- 系统提高时间提醒和总结行为权重；
- AI减少新方案生成；
- 鼓励形成标准、投票或折中方案。

### FINAL_SUMMARY

- 可由用户、AI或系统指定成员总结；
- 总结后不再重新开启大规模讨论。

## 14.4 发言权调度

每一轮由调度器计算候选发言人分数：

```text
发言意愿分
+ 与上一观点的相关性
+ 角色主动性
+ 当前阶段适配度
+ 持有独有信息
+ 被点名权重
+ 长时间未发言补偿
- 最近发言惩罚
- 发言时长超标惩罚
- 重复观点惩罚
```

用户发言具有较高优先级，但系统需要避免用户连续长时间垄断。首期不强制阻止用户发言，只在报告中评估占比和互动质量。

## 14.5 用户交互控制

用户可以：

- 点击“我要发言”；
- 在AI发言中点击“礼貌打断”；
- 点名某位成员；
- 发起投票；
- 请求阶段总结；
- 标记自己愿意做最终总结；
- 查看剩余时间。

“礼貌打断”只影响发言权，不生成用户内容。用户仍需自己说话。

## 14.6 记忆与上下文压缩

讨论上下文分为三层：

1. **原始逐句记录：** 用于回放和报告；
2. **结构化讨论记忆：** 当前观点、标准、分歧、结论、承诺；
3. **短上下文摘要：** 供每次模型调用使用。

结构化记忆示例：

```json
{
  "proposals": [],
  "evaluation_criteria": [],
  "agreements": [],
  "open_conflicts": [],
  "discarded_options": [],
  "current_decision": null,
  "time_remaining_seconds": 420
}
```

不得每轮把整场原始文本直接塞给所有模型，这会导致成本、延迟和注意力退化。

# 15. 评分与反馈体系

## 15.1 评分原则

1. 评分对象是可观察行为，不是人格；
2. 评分必须结合讨论阶段；
3. 评分不能只依赖大模型整体印象；
4. 客观统计、规则判断和模型评价需要分层；
5. 分数必须附带置信度；
6. 不同题型可调整权重，但核心维度保持一致；
7. 报告不提供招聘录用结论。

## 15.2 六个核心维度

### A. 问题分析

观察：

- 是否识别小组目标；
- 是否提出评价标准；
- 是否识别硬约束；
- 是否使用题目材料；
- 是否区分事实、假设和观点。

### B. 观点贡献

观察：

- 是否提出有效新观点；
- 是否给出理由或证据；
- 是否提出可执行方案；
- 是否重复已有观点；
- 是否对最终结果产生实质影响。

### C. 表达沟通

观察：

- 结构是否清晰；
- 发言是否简洁；
- 语速和停顿是否影响理解；
- 是否存在大量口头禅；
- 是否明确回应前文。

### D. 团队协作

观察：

- 是否倾听和承接他人；
- 是否尊重不同意见；
- 是否邀请他人参与；
- 是否避免垄断；
- 是否帮助降低无效冲突。

### E. 推动与组织

观察：

- 是否阶段总结；
- 是否提醒目标和时间；
- 是否推动比较、投票或决策；
- 是否帮助形成共识；
- 是否在合适时机收敛。

### F. 应变与抗压

观察：

- 被质疑时是否回应核心问题；
- 被打断后是否有效恢复；
- 新信息出现后是否调整；
- 时间压力下是否保持清晰；
- 是否能处理不合理成员行为。

## 15.3 评分结构

每个维度包含：

- 0至100展示分；
- 低／中／高置信度；
- 2至5条正面证据；
- 2至5条改进证据；
- 一条下一步训练建议。

展示分不直接由一次大模型调用给出，而由以下组成：

```text
客观行为统计 30%
规则特征评价 25%
语义证据评价 35%
会话完整度和置信度修正 10%
```

具体权重需通过人工标注和试运行校准。

## 15.4 客观行为指标

- 发言总时长；
- 发言次数；
- 平均单次时长；
- 首次发言时间；
- 连续发言次数；
- 主动回应他人次数；
- 点名他人次数；
- 邀请沉默成员次数；
- 阶段总结次数；
- 时间提醒次数；
- 提出评价标准次数；
- 引用材料次数；
- 打断与被打断次数；
- 观点重复率；
- 对最终结论的贡献覆盖。

这些指标不能机械等价为能力。例如发言次数多不自动等于贡献高，打断次数为零也不自动等于协作好。

## 15.5 证据格式

```json
{
  "dimension": "TEAMWORK",
  "impact": "POSITIVE",
  "timestamp_start": "00:08:32",
  "timestamp_end": "00:08:58",
  "quote": "我们可以先把A和C的共同点合并，再讨论预算差异。",
  "context": "讨论存在两个相近方案但尚未整合",
  "interpretation": "用户主动整合他人观点，推动讨论从发散进入比较阶段",
  "confidence": 0.86
}
```

## 15.6 防止虚假精确

- 不显示小数分；
- 证据不足时不强行评分；
- 报告明确说明AI评估存在误差；
- 允许用户标记“不认可此评价”；
- 争议评价进入人工校准样本池；
- 不提供“超过全国93%用户”类排名，除非样本量和标准化条件足够。

# 16. 报告设计

## 16.1 报告首页

必须在30秒内让用户知道：

- 本场整体表现概览；
- 最大优势；
- 最大问题；
- 下一步训练；
- 是否完成讨论目标。

## 16.2 报告结构

1. 本场摘要
2. 六维能力雷达或分项卡片
3. 三个高价值时刻
4. 三个错失机会
5. 讨论时间线
6. 用户发言统计
7. 逐维度证据
8. 最终结论质量
9. 推荐专项训练
10. 与历史场次对比

## 16.3 高价值时刻示例

> 08:32，讨论在两个相似方案之间反复。你将两者共同点归纳为三项，并提出按成本和影响范围比较，帮助小组进入决策阶段。

## 16.4 错失机会示例

> 12:10，候选人B质疑你的方案成本，但你重复了原始观点，没有回应预算约束。更有效的方式是先承认成本问题，再解释如何分阶段实施。

## 16.5 可回放性

用户点击证据卡片后，应跳转到对应文本和音频片段。音频已删除时，至少保留用户授权保存的文本记录。

## 16.6 报告导出

后期支持导出PDF或分享卡，但分享内容默认不包含原始音频、完整对话或敏感信息。

# 17. 专项训练系统

## 17.1 训练单元结构

每个专项训练包含：

- 训练目标；
- 场景说明；
- AI角色行为；
- 时间限制；
- 成功标准；
- 用户作答；
- 即时反馈；
- 可重复练习。

## 17.2 专项训练示例：礼貌反驳

AI说：

> 我认为应该直接选择方案A，讨论成本没有意义，因为我们的首要目标就是扩大影响力。

用户需要在30秒内完成：

1. 承接对方目标；
2. 指出逻辑或约束缺口；
3. 提出替代比较方式。

评分维度：

- 是否正面回应；
- 是否避免人身化表达；
- 是否指出具体问题；
- 是否推动下一步。

## 17.3 自动推荐

报告根据证据推荐不超过3个训练。训练完成后更新能力趋势，但不得用一次短训练直接覆盖完整模拟结果。

# 18. 成长与留存设计

## 18.1 成长不是每日签到

产品不依赖无意义签到。成长系统围绕真实训练行为：

- 完成完整模拟；
- 完成专项训练；
- 修复历史薄弱点；
- 在不同AI角色组合中保持稳定；
- 适应更高难度。

## 18.2 成长档案

展示：

- 最近5场趋势；
- 最稳定优势；
- 反复出现的问题；
- 对不同角色的适应性；
- 不同题型表现；
- 已完成训练计划。

## 18.3 7天冲刺计划

示例：

| 天数 | 内容 |
|---|---|
| 第1天 | 诊断模拟＋报告 |
| 第2天 | 60秒陈述＋建立评价标准 |
| 第3天 | 礼貌反驳＋承接观点 |
| 第4天 | 标准完整模拟 |
| 第5天 | 时间管理＋阶段总结 |
| 第6天 | 压力场专项训练 |
| 第7天 | 最终完整模拟＋成长报告 |

## 18.4 适度提醒

仅在用户主动开启时发送：

- 冲刺计划提醒；
- 购买场次即将过期提醒；
- 面试日期临近提醒；
- 报告生成完成提醒。

# 19. 商业模式

## 19.1 核心原则

群面训练具有短周期和强目标属性，首期以按次付费和冲刺包为主，不强行塑造长期月订阅。

## 19.2 免费层

- 一次60秒陈述练习；
- 一场受限的新手模拟或5分钟体验场；
- 简版反馈；
- 部分专项训练体验。

免费用户必须设置成本上限，避免开放无限语音和多Agent会话。

## 19.3 建议商品

| 商品 | 建议价格区间 | 内容 |
|---|---:|---|
| 单场标准模拟 | 9.9至19.9元 | 完整模拟＋完整报告 |
| 单场压力模拟 | 14.9至24.9元 | 高难度角色和压力事件 |
| 3场训练包 | 24.9至49.9元 | 有效期30至60天 |

| 行业题包 | 后续定价 | 银行、快消、咨询等 |

## 19.4 单场成本目标

目标要求：

- AI、语音、存储和基础设施可变成本控制在售价的15%至25%以内；
- 免费体验成本应低于预期付费转化价值；
- 模型调用支持按阶段路由，不使用最高成本模型处理所有任务；
- 报告生成允许异步，以换取成本和质量。

## 19.5 后期收入扩展

- 高校就业中心账号；
- 培训机构课程包；
- 真人多人练习房；
- 行业专项题库；
- 企业品牌公开训练题，但不接入企业真实筛选决策；
- API或白标版本。

# 22. AI模型与编排架构

## 22.1 模型调用分层

### 低成本快速模型

用于：

- 发言意图分类；
- 是否重复判断；
- 简单摘要；
- 安全检测；
- 候选发言人局部决策。

### 中等能力实时模型

用于：

- AI候选人发言生成；
- 对用户发言的即时回应；
- 讨论状态更新。

### 高能力异步模型

用于：

- 整场证据分析；
- 复杂评分；
- 报告生成；
- 争议样本复核。

## 22.2 模型供应商抽象

业务代码不得直接依赖单一模型SDK。统一接口至少包括：

```python
class LLMProvider:
    async def generate(self, request): ...
    async def stream(self, request): ...
    async def embed(self, request): ...
```

每个请求记录：

- 供应商；
- 模型；
- 场景；
- 输入输出Token；
- 延迟；
- 成本；
- 错误；
- 内容安全结果。

## 22.3 AI候选人生成链路

```text
用户发言完成
  -> ASR转写与分句
  -> 更新讨论结构化记忆
  -> 调度器计算谁需要回应
  -> 角色决策器输出意图
  -> 发言生成器生成短发言
  -> 事实、角色和长度校验
  -> TTS播放
  -> 记录事件并进入下一轮
```

## 22.4 发言生成约束

AI发言必须满足：

- 默认20至60秒；
- 一次最多包含一个主观点和一个补充；
- 明确回应上下文；
- 不编造题目中不存在的数据；
- 不读取后台评分信息；
- 不向用户讲解自己是何种角色；
- 不连续重复类似句式；
- 不以“我完全同意前面同学”作为常规开头；
- 允许表达不完整和有限错误，但不能故意荒谬。

## 22.5 结构化输出

关键模型调用必须要求结构化JSON输出，并通过Schema验证。验证失败时重试或降级，不能将解析错误直接暴露给用户。

# 23. 实时语音方案

## 23.1 首期原则

- 单真人麦克风输入；
- AI逐个输出语音；
- 不要求真正多人同时音频；
- 支持用户主动中断AI播放；
- 语音识别结果实时显示，用户可快速纠正明显错误。

## 23.2 音频链路

```text
浏览器采集音频
  -> 分片上传
  -> 流式ASR
  -> 稳定句确认
  -> 讨论引擎
  -> AI文本回复
  -> TTS分段生成
  -> 浏览器播放
```

## 23.3 延迟目标

公开MVP建议目标：

- 用户停止讲话后1秒内显示稳定转写；
- 2至4秒内AI开始播放首段回复；
- 报告在会话结束后1至3分钟内生成；
- 超过阈值时显示真实状态，不使用虚假“对方正在思考”掩盖长期故障。

## 23.4 打断处理

- 用户点击打断或开始讲话时，停止当前AI音频；
- 记录AI未完成的发言内容，但不自动视为小组已听到；
- AI后续可根据角色选择是否要求继续、让步或回应打断；
- 报告区分用户主动打断与系统音频故障。

# 27. 隐私、安全与合规

## 27.1 基本合规原则

面向中国境内公众提供生成式人工智能服务时，需要关注生成式人工智能服务管理、个人信息保护、网络数据安全和人工智能生成合成内容标识等要求。产品应从设计阶段落实：

- 只收集实现训练所需的最少信息；
- 明确告知音频、转写和模型处理方式；
- 提供查阅、更正、删除和注销能力；
- 不非法保留可识别用户身份的输入与使用记录；
- 建立投诉、举报和内容处置机制；
- AI生成的候选人语音和内容在界面中明确标识；
- 用户导出或公开分享AI生成内容时，根据适用规则处理显式和隐式标识。

## 27.2 敏感数据处理

首期避免采集：

- 人脸视频；
- 身份证；
- 精确住址；
- 正式面试录音；
- 他人未经同意的真实聊天或录音；
- 招聘企业内部保密材料。

用户上传自定义题目时，应提示不得上传公司保密资料。

## 27.3 训练用途声明

必须明确：

- AI候选人均为虚拟角色；
- 评分仅用于训练参考；
- 产品不代表任何招聘企业；
- 产品不保证面试结果；
- 产品不应在正式面试过程中使用；
- 不得使用产品冒充真人或欺骗他人。

## 27.4 内容安全

系统需识别并处置：

- 仇恨、歧视和侮辱；
- 色情和暴力；
- 自残风险表达；
- 违法行为指导；
- 针对真实个人的诽谤；
- 用户通过自定义题目进行骚扰；
- AI角色对用户进行人格攻击。

群面中的合理反驳和压力不等于攻击。内容安全策略必须区分“挑战观点”和“贬低个人”。

## 27.5 安全工程

- 所有密钥仅服务端保存；
- 音频上传使用短期签名；
- 用户之间数据严格隔离；
- 管理后台采用最小权限；
- 支付、权益和退款写入审计日志；
- 重要操作支持幂等和回滚；
- 定期扫描依赖与对象存储权限；
- 防止用户通过Prompt注入让AI候选人泄露系统提示或评分规则。

# 28. 可观测性与成本控制

## 28.1 必须记录的技术指标

- API延迟；
- WebSocket断连；
- ASR首字和最终结果延迟；
- LLM首Token延迟；
- TTS首音频延迟；
- 每个阶段失败率；
- 模型调用错误和重试；
- 单场Token和音频分钟成本；
- 报告生成时间。

## 28.2 单场成本控制策略

- 角色决策与发言生成分离；
- 使用结构化记忆而非完整上下文；
- 实时阶段使用较快模型；
- 复杂报告异步生成；
- 缓存题目材料和固定角色配置；
- 限制AI发言长度；
- 免费体验限制总时长和AI人数；
- 失败调用自动熔断并切换备用模型。

## 28.3 质量和成本的优先级

不能为了降低成本让角色失去差异、报告失去证据或语音延迟无法接受。优先削减：

1. 非核心视觉生成；
2. 重复报告文案；
3. 过长AI发言；
4. 无必要的多次模型复核；
5. 免费层时长。

# 29. 质量评估体系

本节不是传统软件测试方案，而是规定“产品是否真的像群面训练”的质量标准。

## 29.1 模拟真实性指标

- 三名AI角色的发言风格和行为可被盲测区分；
- AI不会持续一致赞同用户；
- 每场至少形成一个真实分歧；
- 分歧能够在规则控制下收敛或明确保留；
- AI发言不大段重复题目；
- 用户有合理发言机会；
- 讨论目标在时间内可完成。

## 29.2 评分可信度指标

- 每个重要结论至少有一条证据；
- 时间戳和原话准确；
- 不同评分运行结果保持基本稳定；
- AI评分与人工教练评分在核心维度上达到可接受一致性；
- 用户“不认可”反馈可追踪；
- 不因用户口音、性别或声线造成不合理评分差异。

## 29.3 人工校准

建立小规模专家标注集：

- 同一场对话由至少两名具备群面辅导经验的评审独立评分；
- 记录分歧；
- 校准维度定义；
- 用于比较评分模型版本；
- 不直接把少量专家偏好包装成绝对真理。

# 32. 项目验收标准

## 32.1 核心流程验收

- 用户可完成从选题到报告的完整流程；
- 讨论状态在刷新或短断线后能够恢复；
- 权益不会重复扣减；
- 系统故障场次可自动返还；
- 用户可删除训练记录；
- 题目和评分规则均有版本记录。

## 32.2 体验验收

- AI角色在绝大多数场次中具有可感知差异；
- 用户停止发言后，AI首段反馈延迟处于可接受范围；
- 讨论不会长期陷入AI相互复述；
- AI不会替用户完成答案；
- 报告首页能明确给出优势、问题和下一步训练。

## 32.3 报告验收

- 重要评分有对应证据；
- 证据时间戳正确；
- 报告不输出录取概率；
- 报告不使用歧视性或人格定性语言；
- 不完整会话明确降低置信度；
- 用户可反馈评价是否准确。

## 32.4 安全验收

- 前端无模型密钥；
- 用户数据隔离；
- 对象存储默认私有；
- 支付回调幂等；
- 管理操作有审计；
- 账号删除和数据删除可执行；
- AI生成身份有明确标识。

# 34. 主要风险与应对

## 风险1：AI角色像同一个人

**应对：** 参数化角色、私有立场、不同决策策略、盲测区分、发言结构去重复。

## 风险2：讨论不自然、延迟高

**应对：** 半轮次制、短发言、结构化记忆、模型分层、TTS分段、允许用户打断。

## 风险3：评分看似专业但不可信

**应对：** 证据化、置信度、人工校准、用户反馈、规则与模型分层。

## 风险4：题目数量多但质量差

**应对：** 题型模板、结构化生成、人工审核、版本管理、先少量精品题。

## 风险5：用户生命周期短

**应对：** 场次包、7天冲刺、专项训练、行业增值包，不依赖长期订阅。

## 风险6：免费用户造成高成本

**应对：** 限时体验、低成本模型、次数限制、免费报告简化、成本监控。

## 风险7：产品被用于真实面试作弊

**应对：** 不开发隐蔽提词功能；不支持悬浮窗；服务协议禁止；产品流程围绕训练场景。

## 风险8：语音和个人信息合规

**应对：** 首期不采集视频；最小化保存；明确同意；删除能力；生成内容标识；隐私影响评估。

## 风险9：用户把评分当成企业标准

**应对：** 明确训练用途；不冒充企业；不提供录用预测；报告展示局限性。

## 风险10：一个人开发范围失控

**应对：** 严格执行版本边界；内部文字版先验证；不在P1阶段开发支付、视频或App。

# 38. 最终产品定义

本项目不是：

- 群面答案生成器；
- 群面题库网站；
- 多个聊天机器人同时说话；
- 录取概率测试；
- 正式面试作弊助手。

本项目是：

> 一个由通用题型引擎、参数化AI候选人、受控讨论编排器和证据化评分系统组成的群面能力训练平台。

第一阶段的成功标准不是题目多、页面多或模型数量多，而是：

1. 用户能独自完成一场有真实互动感的群面；
2. 三名AI候选人表现出稳定且有意义的差异；
3. 报告能指出具体发言中的有效行为和问题；
4. 用户知道下一步应该练什么；
5. 用户愿意再练一场并为此付费。
